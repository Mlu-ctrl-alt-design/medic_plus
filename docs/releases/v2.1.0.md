# medic_plus v2.1.0

**Release date:** 2026-05-09
**Theme:** Signup admin overrides — Force Provision + Admin Mark Paid

This release closes a gap on the doctor self-registration funnel where a Practice Registration Request that paid out-of-band, or whose Yoco webhook was lost, had no path to completion short of editing the database. System Managers now have two buttons on the Practice Registration Request form to re-trigger or override.

## What's new

### Force Provision (System Manager only)

When a PRR is `payment_status=Paid` but stuck before provisioning (e.g. webhook landed, but the provisioner crashed), the form now shows a **Force Provision** action under "Actions". One click re-runs the canonical webhook path — same code as a real Yoco webhook, so the resulting tenant is byte-identical.

Hard prerequisites:

- Caller must be a System Manager
- PRR must exist
- PRR must be Paid
- PRR must not already be provisioned

Cherry-picked from `feature/phase-7b-bulk-import` commit `55bdf3b` — written months ago, never previously merged.

### Admin Mark Paid + Provision (System Manager only)

When a PRR is **not** Paid and not yet provisioned, the form shows a **Mark Paid (Admin Override)** action. Clicking it opens a dialog that requires a **reason** (e.g. "EFT received 2026-05-09, ref 12345" or "Complimentary — internal demo"). On submit:

1. An audit Comment is written to the PRR timeline citing the actor and the reason — recorded *before* anything else, so the override is traceable even if provisioning fails.
2. `payment_status` is flipped to `Paid` and `yoco_paid_at` is stamped (same fields as a real Yoco webhook).
3. The same `_handle_payment_succeeded` path runs to provision the tenant.

Hard prerequisites:

- Caller must be a System Manager
- PRR must exist
- PRR must not already be provisioned

The action is idempotent for already-Paid requests (the override flag in the response is set to `false` so the UI knows it wasn't a payment flip — useful for retry semantics).

### Open Practice shortcut

Once a PRR has been provisioned, an **Open Practice** button on the same form jumps straight to the resulting Practice record.

## Side fix: applicant mobile now propagates

Before this release, the applicant's mobile number was captured on the PRR and the User but silently dropped during downstream provisioning. Both `Healthcare Practitioner.mobile_phone` and `Practice.phone` are now persisted from the PRR. Existing records are unaffected (no backfill).

## Behind the flag

Nothing — both buttons are controlled by `frappe.user_roles.includes("System Manager")` on the client and a server-side role check on the whitelisted method. No site config flags.

## Out of scope (deferred)

- A bulk admin "Mark Paid + Provision" action in the PRR list view — single-record only for now.
- Automatic suggested reasons (e.g. EFT lookup against a reconciliation feed) — admin types the reason free-form.
- A dedicated audit doctype for overrides — comments on the PRR timeline are the audit trail.
